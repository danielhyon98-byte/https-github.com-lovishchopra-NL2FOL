# engine — validation, compilation, decision, provenance

| Module | Purpose |
| --- | --- |
| `validator.py` | Parses untrusted JSON into a `Problem` (size and depth guards) and checks identifiers, strict sorts (no Int/Real mixing without `to_real`), policy (constant non-zero divisors; nonlinear terms off by default) and limits. Collects every diagnostic; maps E1xx/E3xx to INVALID_FORMALIZATION and E2xx to UNSUPPORTED. |
| `compiler.py` | Maps each validated node to exactly one Z3 call in a fresh `Context`; numerals from text so `0.1` is the rational 1/10; `idiv`/`mod` follow Z3 integer semantics; exports exact SMT-LIB text for audit. |
| `procedures.py` | `run_consistency`, `run_satisfiability`, `run_entailment`. Entailment checks consistency first (no vacuous proofs), then asserts premises and the negated conclusion under tracking literals so the unsat core names the premises relied on. Models are extracted exactly (`a/b`). Unknown answers are classified TIMEOUT or UNKNOWN; never success. |
| `provenance.py` | Version capture, binding digests over (problem, config, versions), HMAC-SHA256 signing and constant-time verification. |
| `runner.py` | `verify(...)`: validate → compile → decide → bind → sign. Never raises; every failure is a bound non-success result. Also lists `ungrounded_dependencies`: relied-on premises with missing, inferential, assumed or failed grounding. A definitive status that used no premise carries `E108` (vacuous), and so does a COUNTEREXAMPLE over zero premises (it says only that the conclusion is no tautology: nothing the claim rests on was encoded). A COUNTEREXAMPLE over at least one premise that falsifies the conclusion only through numeric symbols no premise mentions carries `E111` (unencoded reason: Z3 decides `premises AND forall free. NOT conclusion` unsat, so every premise assignment leaves a value of those figures that makes the conclusion true; the claim's own reason was not encoded); a Bool point no premise links to stays the non sequitur COUNTEREXAMPLE. An ENTAILED proof whose relied-on premises restate the conclusion (it, or each of its "and" conjuncts, is syntactically a relied-on premise or a conjunct of one: `circular_premises`) carries `E112` (circular) when every restating premise is the writer's own (`assumed_grounding`: an ungrounded kind or an unverified `arithmetic_fact`); restating a task setting, a rubric rule or a text is a transcription check, not a circle. A COUNTEREXAMPLE that only reassigns a figure the problem defines but never asserts carries `E110` (unasserted figure): a premise `b <-> (n = 17)` (a Bool atom defined by a comparison of numeric symbols) whose numeric symbols no other premise mentions asserts nothing, so when the entailment, re-run with each such atom asserted, is ENTAILED, the counterexample merely sets the stated figure to another value; the diagnostic names the premise, its label, the atom and the values the counterexample chose. The status stays COUNTEREXAMPLE (the solver's answer about the encoding, as it stays ENTAILED under `E112`); the outcome layer never displays any of `E108`, `E110`, `E111`, `E112` as a verdict. `unasserted_figure_definitions(problem)` is the syntactic test (no solver) the translator shares. |
| `statuses.py`, `errors.py`, `results.py` | Closed status taxonomy with `is_definitive`, stable diagnostic codes, and result models including the scope statement. |

Resource bounds come from `SolverConfig` (per-check timeout, optional `rlimit`,
seed, optional memory budget). The memory budget is per verification while Z3's
limit is process-global, so the engine applies the budget times the number of
verifications running at once and only raises the limit while any runs; lowering
it under load made Z3 abort and the next solver call crash the process. Stress
results for this package are in `tests/stress/results/` and summarized in
`docs/STRESS_RESULTS.md`.
